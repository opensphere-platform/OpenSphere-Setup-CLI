# Setup CLI 독립 실행 계약

상태: 사용자의 2026-09-03 요구를 반영한 현재 제품 기준.
적용: 0.5.0-edge.20 이후. edge.19의 매번 임시 다운로드·삭제 정책을 대체한다.

Setup은 Windows에 설치해 상시 운영하는 프로그램이 아니다. 필요할 때 실행해 Kubernetes의 Console을 준비·설치·검증하고 종료한다. **무설치는 매번 다운로드를 뜻하지 않는다.**

## 기본 동작에서 금지

- Setup의 LocalAppData/Program Files/사용자 bin/npm global 설치
- 사용자·시스템 PATH, shell profile, 서비스, 예약 작업, 시작 프로그램 등록
- 상주 프로세스 및 사용자가 찾기 어려운 공용 런타임 캐시
- bootstrap/upgrade의 부수 효과로 os CLI 설치
- 명시적 요청 없는 호스트 인증서 신뢰 등록

## 실행 흐름

`EXE → exact Release 선택 및 온라인 immutable 메타데이터 검증 → 보관 버전 확인 → 없으면 한 번 다운로드·검증·압축 해제 → 있으면 원본 ZIP 및 전체 파일 검증 → CLI 실행 → 자식 종료 대기 → 동일 종료 코드`

보관은 EXE 옆의 `opensphere-setup-runtime/<release-tag>/`를 사용한다. 현재 작업 폴더와 무관하다. ZIP·SHA256SUMS·압축 해제한 런타임을 함께 유지한다. 같은 버전이면 다시 다운로드하거나 압축 해제하지 않는다. 버전이 바뀌면 별도 폴더에 준비하고 이전 버전은 자동 삭제하지 않는다. Windows 설치·PATH 등록·서비스 등록은 없다.

공개 채널 포인터와 immutable Release 메타데이터의 작은 온라인 조회는 실행마다 유지한다. GitHub asset digest로 보관 ZIP·SHA256SUMS를 검증하고, 실행 파일과 DLL을 포함한 전체 런타임의 SHA-256을 검증된 원본 ZIP의 내용과 대조한다. 추가 파일, 누락, 링크, 경로 이탈, 잘못된 hostInstallation 정책을 거부한다. 보관 파일 검증 실패는 실행 차단이며 자동 덮어쓰기·버전 자동 후퇴로 대체하지 않는다.

Windows 기본은 최초 다운로드 후 재사용하는 포터블 실행기다. 모든 런타임이 내장된 작은 오프라인 단일 파일은 아니다. 첫 ZIP은 버전당 약 174MB, 보관 총량은 약 610MiB다. 내부 약 99MiB Node SEA와 PowerShell/kubectl의 용량은 남는다. 네이티브 경량화는 별도 미완료 과제다.

## 생명주기

버전별 OS 잠금으로 동시 다운로드를 하나로 합친다. 검증이 완료된 고유 staging 디렉터리만 원자적으로 버전 폴더로 승격한다. 준비 후 잠금을 해제하므로 실행 명령 자체는 직렬화하지 않는다. 정상 완료·명령 실패·취소 후에도 완료된 런타임은 보존한다. 다운로드 실패·처리 가능한 취소는 해당 staging만 정리한다. 강제 종료·전원 장애의 미완성 폴더는 재사용하지 않고 다른 실행의 파일을 포괄 삭제하지 않는다.

EXE 위치가 쓰기 불가능하면 쓰기 가능한 위치로 이동하도록 안내한다. 호스트의 다른 위치로 숨겨 설치하거나 권한 상승을 요구하지 않는다. EXE와 보관 폴더를 함께 옮기면 재사용할 수 있다. 모든 Setup 명령을 종료한 뒤 두 항목을 삭제하면 제거된다. 손상된 버전만 다시 받을 때에는 안내된 해당 버전 폴더만 제거한다.

호출자의 cwd와 stdin을 보존한다. registry token을 launcher가 읽거나 기록하지 않는다. lock/receipt는 사용자 작업 결과이며 런타임 보관 폴더와 별개다. `install-cli`와 `bootstrap --trust-local-ca`는 별도 명시적 호스트 변경이다. Kubernetes 변경은 사용자가 실행한 bootstrap/upgrade 등 작업 명령에 한정한다.

## 수용 기준

1. 전역 Setup 설치·PATH 변경 없이 실행한다.
2. Setup 버전·채널과 Console release 선택을 분리한다.
3. 동일 버전의 두 번째 실행은 runtime ZIP·SHA256SUMS를 받지 않고 이미 풀린 파일을 검증해 사용한다.
4. 새 버전은 분리 보관하며 이전 버전을 덮어쓰지 않는다.
5. 동시 첫 실행, 명령 실패, 다운로드 중단, 변조 및 링크를 검증한다.
6. bootstrap/upgrade는 os CLI를 자동 설치하지 않는다.
7. 온라인 메타데이터 조회·최초 다운로드·디스크 사용량 및 내부 런타임 크기 한계를 숨기지 않는다.
